# agent-polygraph v0.4.0 — executable guard verification

Prepared for OIDC staged publishing. This document does not establish public npm availability. Check the registry and public-install verification after maintainer approval.

- Add `guard --install --mode verify --test-command "npm test"`: execute an explicitly selected command in the fixed project folder at Stop, including stops without any passing-test claim and continued stops after repairs.
- Default to fresh execution without pass caching. Add optional content/environment-bound, expiring pass reuse for deterministic local suites.
- Treat failures, timeouts, incomplete fingerprints and net working-tree changes explicitly. Bound repair attempts (two consecutive attempts per repair cycle by default), then surface an unresolved result rather than silently allowing a claim or continuing forever.
- Add transcript-only `--mode strict` for ambiguous passing-test claims and `--on-unknown warn` as an explicit, visible relaxation of executable verification's default stop policy.
- Add private `guard --status` receipts with actual execution/repair counts and outcomes. Persist no raw output, commands or source contents. Serialize verifiers per project and report abandoned locks.
- Bind executable policy to a project and reject global installation. Encode policy transport so shell metacharacters cannot rewrite the installed hook arguments. Hook permissions remain the execution boundary; this is not a sandbox or adversarial tamper-proof enforcement.
- Extend the real-test comparison and the packed npm release check to exercise the executable policy, including an actual failed command followed by repair and retest. Preserve the existing claim-only benchmark and historical evidence.

The package and Claude plugin manifests both use 0.4.0. The default claims policy and plugin remain compatible. To enable stronger behavior, reinstall the project's guard with an explicit mode and command, then review the changed Codex hook when prompted. This release adds no package dependencies.

Full-suite coverage comes from the command you choose. Caching cannot cover ignored inputs or external service changes. Before/after fingerprints cannot prove there were no transient changes. Independent human accuracy evaluation of the transcript classifier remains outstanding; the new verification mode does not manufacture those labels.

Local validation: 146 tests passed on Node 24; the existing 25-case claim-only replay passed; the extended 12-scenario executable comparison detected all 7 failing fixture suites using 12 test executions; an isolated installation of the actual packed tarball detected an unclaimed failure, retested a repair and recorded both executions. These are authored regression checks, not independent field accuracy measurements.
